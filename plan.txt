# SkillVerse 2.0 — Master Plan (Business + Architecture + Design + Delivery)

## 0. Context

SkillVerse today is an Express + MongoDB + Redis + Socket.io backend with a React 18/Vite SPA. The code quality is decent (ledger idempotency, safe error handling, helmet, rate limits), but it **cannot run on Cloudflare's free tier** (long-running server, local-disk uploads, `child_process` code runner, Redis, node-cron, Mongoose TCP driver). It is also not a business yet: there is no real marketplace, payouts, subscriptions, ads, legal pages or compliance.

**Goal:** rebuild SkillVerse into a production-grade, revenue-generating skill-sharing platform (courses, certifications, mentoring, skill-swap, subscriptions, ads). It will be deployed for **$0 on Cloudflare**, be secure by design, be documented as it is built, and install with one command.

**Decisions from Q&A**
- Market: **India first (Razorpay, INR), global later** (Stripe behind the same payment adapter).
- Delivery: **phased roadmap**. Every phase is independently deployable.
- Stack/DB: my choice (below). There must be **no cold starts** that degrade the user experience.
- Cost: **stay on the free plan for building and presenting**. You decide about the $5 Workers Paid plan at launch.

### Your $5 question, answered plainly
The Cloudflare free plan has two different kinds of limits:
1. **Per-request CPU: 10 ms.** This does NOT depend on the number of users. Every single request gets 10 ms of pure CPU time (waiting on the database or network doesn't count). The architecture is designed so that normal requests use 1–5 ms. Heavy work (PDFs, hashing-heavy tasks, video) is pushed to the browser or to queues.
2. **Daily quotas.** The main one is 100,000 Worker requests/day. This DOES depend on users. At roughly 50–100 requests per active user per day, the free plan comfortably serves ~1,000–2,000 daily active users. Beyond that, requests fail until midnight UTC.

So: **free is enough for development, demos and early users.** You only need the $5/month plan when you have real traffic (10M requests/month plus 30 s CPU per request). Nothing in the code has to change when you upgrade; it's a billing toggle.

## 1. Technology decisions (and why)

| Concern | Choice | Why |
|---|---|---|
| API runtime | **Cloudflare Workers + Hono (TypeScript)** | Zero cold starts (solves the Render problem), global edge, free. Hono is Express-like, fast and typed. |
| Web app | **React 19 + React Router v7 (framework mode, SSR) on Workers** | Keeps your React knowledge. SSR is needed for SEO (course pages must rank) and for **AdSense approval**, which needs crawlable content. |
| Database | **Cloudflare D1 (SQLite) + Drizzle ORM** | Free (5 GB total, 500 MB per DB, 5M reads and 100k writes/day), no cold start, relational. Money, orders, enrollments and payouts need SQL constraints and joins. Drizzle keeps a clean exit path to Postgres (Neon/Supabase via Hyperdrive) if we outgrow it. *Why not Mongo/MySQL:* neither runs reliably or for free inside Workers. Free external DBs (Atlas, Neon) add latency, and Neon adds cold starts. |
| Files & video | **Cloudflare R2** (10 GB free, zero egress) + presigned direct uploads | Browser → R2 directly, so large files never pass through the Worker. YouTube/Vimeo unlisted embeds are also supported as a free lesson source. Cloudflare Stream is an optional paid upgrade later. |
| Images | Cloudflare Image Transformations (5k free/month) | Resize and WebP/AVIF on the fly. |
| Cache / flags / rate limits | **Workers KV** + **Workers Rate Limiting binding** | Replaces Redis. |
| Realtime | **Durable Objects (SQLite-backed, on the free plan) + WebSocket Hibernation** | Notifications, chat, live contest leaderboards. Replaces Socket.io. |
| Background jobs | **Cloudflare Queues** (free tier) + **Cron Triggers** | Emails, webhooks, payout reconciliation, digests, streak resets. Replaces node-cron. |
| Search | **D1 FTS5** full-text now → **Vectorize + Workers AI** semantic search later | Free. |
| AI features (later) | **Workers AI** (free daily allowance) | AI tutor, quiz generation, captions (Whisper), moderation (Llama Guard). |
| Code execution | **In-browser runners** (Pyodide, JS in a sandboxed Web Worker) for "Run"; **Judge0 (RapidAPI free tier)** for graded "Submit" | Workers can't run untrusted code, and the current `local.adapter.js` executes untrusted code on the host. That is dangerous and it will be deleted. |
| Payments | **Razorpay** (Orders, Payment Links, Subscriptions, **Route** for instructor payouts), called over REST with `fetch` | India-first, UPI. Behind a `PaymentProvider` interface so Stripe can be added later. |
| Email | **Resend** (3,000/month free) through a Queue-backed outbox | Transactional email. |
| Bot protection | **Cloudflare Turnstile** (free) | Signup, login, contact forms, reviews. |
| Admin protection | **Cloudflare Access (Zero Trust, free ≤50 users)** in front of `/admin` | Admin requires your Google identity at the edge before the app is even reached. |
| Validation | **Zod** schemas in a shared package | The same rules run in the browser and the API. |
| API docs | `@hono/zod-openapi` → OpenAPI 3.1 + Scalar UI at `/api/docs` (dev/staging) | Docs generated from code, so they never go stale. |
| UI | **Tailwind CSS v4 + shadcn/ui (Radix)** + lucide icons + Motion | Accessible primitives. You already use Radix. |
| Tests | Vitest + `@cloudflare/vitest-pool-workers` (API runs inside real workerd with local D1), Testing Library, **Playwright** E2E | Tests run in the actual production runtime. |
| Monorepo | **npm workspaces + `concurrently`** at root | As you requested; Windows-friendly. |
| Observability | Workers Logs (free), Cloudflare Web Analytics, Sentry free tier (opt-in), UptimeRobot | Free. |

**Same-origin routing (a key security decision):** production serves everything from one domain. `skillverse.in/*` goes to the web Worker and `skillverse.in/api/*` goes to the API Worker (Workers Routes). The web Worker's SSR loaders call the API through a **Service Binding**, which is internal and has zero network hops. Being same-origin means no CORS surface, strict `__Host-` cookies and simpler CSRF defense. In local dev, the Vite proxy (`/api` → `localhost:8787`) mirrors this.

**Domain:** you'll need your own domain (~₹800/year via Cloudflare Registrar). Razorpay activation and AdSense approval both require one. `*.workers.dev` works for demos and staging.

## 2. Business model — how SkillVerse earns

All rates below are **admin-configurable in `platform_settings`**. The numbers are sensible defaults.

| # | Revenue stream | How it works | Default split |
|---|---|---|---|
| 1 | **Course marketplace** | Instructors sell courses (free or paid, ₹199–₹4,999). | Platform-driven sale: **70% instructor / 30% platform**. Sale through the instructor's own link or coupon: **95 / 5**. |
| 2 | **SkillVerse Plus** (subscription) | ₹299/month or ₹2,499/year. Unlocks the "Plus catalog", is ad-free, and adds unlimited practice submissions, AI tutor, and 1 free cert exam attempt per quarter. | **50% of net subscription revenue** forms an instructor pool, paid out monthly by engaged watch-minutes (Skillshare/Udemy PP model). |
| 3 | **Paid certifications** | Proctored-lite timed exams (₹499–₹1,999, retake fee). Verifiable certificate with a QR code, a signed credential and a LinkedIn "Add to profile" button. Partner-authored exams are also possible. | Platform exams: 100%. Partner exams: 70 / 30. |
| 4 | **1:1 mentoring & live sessions** | Mentors set hourly rates and availability. Learners book and pay upfront; funds are held until the session completes. | **85 mentor / 15 platform**. |
| 5 | **Cohorts & live workshops** | Seat-capped, scheduled group classes with ticketing. | 80 / 20. |
| 6 | **Advertising: Google AdSense** | Display ads on free surfaces only (catalog, blog, practice, free course pages) for non-Plus users. Consent-gated, with house ads as fallback. | 100% platform. |
| 7 | **Sponsored listings (first-party ads)** | Instructors pay per click (from wallet) to boost courses in search and category pages, clearly labeled "Promoted". | 100% platform. |
| 8 | **Credits / wallet & gift cards** | Existing credit packs are kept: buy credits, spend on courses, exams, boosts and streak freezes. Gift cards. | Float + breakage. |
| 9 | **Referral / affiliate program** | Users earn wallet credits for referrals. Affiliates earn a % on first purchases. | Marketing cost. |
| 10 | **Teams / B2B** (later) | Companies buy seats (~₹999/seat/year). Admin dashboard, assigned learning paths, progress reports. | 100% platform (instructors paid from pool). |
| 11 | **Careers / hiring** (later) | Paid job posts and recruiter subscriptions to search **certified** talent (opt-in by learners). | 100% platform. |
| 12 | **Contest sponsorships** | Companies sponsor coding contests and prizes for branding and hiring. | 100% platform. |

**Free engagement engine (drives traffic, which drives ads, subscriptions and sales):** free courses, **skill-swap** (barter teaching using time-credits, e.g. "I teach Guitar, you teach Excel"), practice arena, contests, streaks/XP/leaderboards, community Q&A, public profiles and portfolios.

**Supply side (instructors):** anyone can **apply to teach**. The application is a profile, a sample lesson and topic expertise. Before a paid course goes live it passes a **course review queue** (quality bar). Your existing "earned teaching" milestone model is kept as a **fast-track**: high-XP learners are auto-approved as community mentors/skill-swappers. Paid payouts require **KYC through Razorpay Route's hosted onboarding**. We store only the Razorpay linked-account ID, never bank details or PAN.

**India compliance** (to confirm with a CA before launch; documented in `docs/business/compliance.md`):
- GST 18% on digital services, with GST invoices (GSTIN when registered).
- TDS under section 194-O as an e-commerce operator on instructor payouts.
- **DPDP Act 2023**: consent, grievance officer, data export and deletion.
- Razorpay activation requires Terms, Privacy, Refund/Cancellation, Contact and Pricing pages.
- AdSense needs a Privacy Policy plus a Google-certified CMP for EEA/UK visitors.
- Financial records are retained for 8 years even after account deletion (anonymized).

**Refund policy (default):** 7 days and <30% of the course consumed → automatic refund. Exams are refundable only before the first attempt. Mentoring is refundable if cancelled >24 h before the session.

## 3. System architecture

```
Browser ──HTTPS──► Cloudflare edge (WAF, Turnstile, Access for /admin, cache)
                    │
                    ├── skillverse.in/*        → web Worker (React Router v7 SSR + static assets)
                    │                              └─ Service Binding ─┐
                    └── skillverse.in/api/*    → api Worker (Hono) ◄───┘
                                                  ├─ D1 (primary DB, FTS5)
                                                  ├─ KV (sessions cache, flags, settings)
                                                  ├─ R2 (media: private bucket + public bucket)
                                                  ├─ Durable Objects (NotificationHub per user, ChatRoom, ContestRoom)
                                                  ├─ Queues (email, webhooks, media-scan, payouts, analytics)
                                                  ├─ Cron (streaks, reconciliation, digests, cleanup, backups)
                                                  ├─ Rate Limiting binding
                                                  └─ External: Razorpay, Resend, Judge0, Google OAuth, AdSense, Workers AI
```

**API layering** (`apps/api/src`): `routes/` (HTTP + OpenAPI schema only) → `services/` (business logic, pure and testable) → `repositories/` (Drizzle queries) → `db/schema`. Cross-cutting pieces live in `middleware/` (auth, rate-limit, audit, error, request-id, security headers) and `policies/` (a single place for every authorization rule: `can(user, 'course.edit', course)`).

**D1 transaction rule:** D1 has no interactive transactions, only atomic `batch()`. All money and ledger writes are built as a single `batch()` with **conditional guards** (for example `UPDATE … WHERE status='pending'` plus idempotency keys). This is documented in `docs/architecture/adr/0004-d1-atomicity.md`.

## 5. Security architecture (secure by default)

Target: **OWASP ASVS Level 2**, documented in `docs/security/`.

**Authentication**
- Sign-in methods: Google OAuth (PKCE + state + nonce), email + password, and email OTP / magic link. Passkeys (WebAuthn) come in a later phase.
- Passwords: PBKDF2-SHA256 with 100k iterations (the Workers WebCrypto max, native code) and a per-user salt. The hash format is versioned (`pbkdf2$100000$salt$hash`) so it can be upgraded to Argon2 on Workers Paid without forcing resets. Signup checks the **HIBP Pwned Passwords** k-anonymity API. Minimum length is 10 with no composition rules (NIST 800-63B).
- **Sessions, not JWTs:** a 256-bit random token in a `__Host-sv_session` cookie (HttpOnly, Secure, SameSite=Lax, Path=/). Only the SHA-256 of the token is stored in D1 (cached in KV for 5 min). Sessions have a 7-day rolling idle timeout and a 30-day absolute limit. They are rotated on privilege change, can be revoked individually, and "sign out everywhere" is supported. Instant revocation is the reason this beats JWT refresh rotation.
- **MFA:** TOTP plus recovery codes. It is **mandatory for admins and for anyone receiving payouts**, and optional for everyone else. Changing email, password, payout details or 2FA requires re-authentication (step-up).
- Brute force protection: per-IP and per-account rate limits, Turnstile after 3 failures, generic error messages (no user enumeration), timing-safe comparisons.
- Email verification is required before purchasing, teaching, posting or booking.

**Authorization**
- Roles: `learner`, `instructor`, `mentor`, `moderator`, `org_admin`, `admin`, `super_admin`.
- Every route declares a policy. Ownership checks live in `policies/` and each one has tests.
- Deny by default: any route without a declared policy fails a test.
- `/admin` is double-gated: **Cloudflare Access** at the edge plus the app role plus MFA.

**Input/output**
- Zod validation on every body, query and param. Unknown keys are rejected. Sizes are capped.
- Drizzle parameterized queries only; any raw SQL template is lint-banned.
- User rich text is Markdown rendered through `rehype-sanitize`. Raw HTML is never rendered and `dangerouslySetInnerHTML` is lint-banned except inside a sanitizer wrapper.
- Errors never leak internals. Each error carries a request ID (this pattern is ported from the current `server.js`).

**Headers**
- Strict CSP with per-request **nonces** (possible because of SSR), with an explicit allowlist for Razorpay checkout, AdSense, Turnstile and Google OAuth.
- HSTS preload, `frame-ancestors 'none'` (except Razorpay's needs), COOP, a strict Permissions-Policy, `nosniff`, and `Referrer-Policy: strict-origin-when-cross-origin`.

**CSRF:** same-origin plus SameSite=Lax, plus an `Origin` header check on every non-GET request, plus a required custom header on the JSON API.

**Files**
- Uploads use presigned R2 PUTs with enforced content-type, max size and a random key.
- A Queue consumer verifies magic bytes after upload and quarantines anything that fails.
- User content is served from a separate `media.` host with `Content-Disposition` and `nosniff`. SVG and HTML are never served inline. Images are re-encoded through Image Transformations.

**Paid media**
- Short-lived (10 min) HMAC-signed URLs bound to user + lesson, plus a visible user-ID watermark overlay.
- Honest limit: screen recording can't be prevented, only deterred.

**Payments**
- Prices are always computed server-side from the DB, never trusted from the client.
- Webhooks are verified with HMAC over the **raw body**. The current code verifies over `JSON.stringify(req.body)` after the sanitizer has mutated it; that bug is fixed in the rewrite.
- Idempotency: every provider event ID is UNIQUE in `webhook_inbox`.
- The ledger is immutable double-entry.
- A daily **reconciliation cron** compares against the Razorpay API and alerts on drift.
- Refunds are 2-step for large amounts.

**Exams & anti-cheat**
- Answers never reach the client.
- Per-attempt randomized pools and seeds, server-authoritative timers, tab-visibility and paste events logged.
- Code-similarity checks on submissions.

**Abuse**
- Rate Limiting binding tiers (anonymous, authenticated, sensitive).
- Turnstile on public forms.
- Report and moderation queue, with Workers AI moderation (Llama Guard) on posts.
- Sponsored-ad click fraud dedupe (per user/IP/day).

**Secrets**
- Stored with `wrangler secret`. Local secrets live in `.dev.vars`, which is gitignored and **auto-generated by the setup script**.
- **gitleaks/secretlint pre-commit hook.**
- No secrets are ever sent to the web bundle; the build fails if a `VITE_`/client env var name looks like a secret.

**Privacy (DPDP/GDPR)**
- Consent banner (Google CMP for ads), with a "decline non-essential" option as prominent as "accept".
- Data export as JSON.
- Account deletion: soft-delete, then hard-delete and anonymize after 30 days, keeping financial records as required by law.
- IPs are stored only as salted hashes. PII is redacted from logs.

**Supply chain**
- Lockfile committed. `npm audit` and dependency review in CI. Renovate/Dependabot. Pinned GitHub Actions.

**Documents:** `SECURITY.md` (disclosure policy), `docs/security/threat-model.md` (STRIDE per component), `docs/security/asvs-checklist.md`, `docs/security/incident-response.md`.

## 6. Product surface & UI design

**Design direction:** clean, content-first and trustworthy (Coursera clarity plus Linear polish). The violet brand is kept but toned down. Glassmorphism appears only on marketing hero sections, never on reading or learning surfaces, for legibility.

**Design system** (`apps/web/app/styles/tokens.css` + `docs/design/design-system.md`):
- Semantic CSS-variable tokens (surface, text, border, brand, success/warn/danger), with full light and dark themes that follow the system setting and have a manual toggle.
- Type scale: Inter (UI) plus a display face. 4px spacing grid, radius and elevation scales.

**Ad placement policy** (`<AdSlot placement=… />`)
- Renders only when: ads are enabled in admin, the user isn't Plus/Teams, the page type is on the allowlist, and consent has been given.

## 6A. Signature features (what makes SkillVerse different)

These go beyond the standard course marketplace. Each one is tagged with the phase that delivers it (see §8).

**Proof of skill (trust and hiring value)**
1. **Skill Passport** (P4): a public, shareable profile (`/@username`) that gathers certificates, exam credentials, contest ranks, finished projects, peer endorsements and mentoring reviews. It includes a **"Skill DNA" radar chart** and a QR code. Recruiters search Passports in P7. It is the product's "LinkedIn for proven skills" hook.
2. **Capstone projects + peer review** (P4): courses can end with a real project. Other learners who have already finished that course review submissions against a rubric and earn credits and XP for good reviews. Mentors can be hired for paid expert reviews. Every verified project goes onto the Passport.
3. **Teach-back** (P3): the learner records a 2-minute explanation (audio/video/text) of a concept (the Feynman technique). Peers and an AI rubric (Workers AI) score it. Good teach-backs earn XP and count toward the **instructor fast-track**. This turns learners into future teachers, which grows supply.

**Discovery and demand**
4. **Skill Map** (P3): visual, interactive career roadmaps shown as a tree (for example "Full-stack dev", "Digital marketing", "Guitar"). Each node links to courses, problems, mentors and exams, and fills in as you progress.
5. **Skill Snacks** (P6): a vertical feed of short 60-second lesson clips cut from courses by instructors, with a "Continue full course" CTA. It serves discovery and ad inventory for free users.
6. **Demand Radar for instructors** (P2): shows what learners search for and don't find, plus bounty requests, with demand scores. Instructors can see exactly which course to build next.
7. **Skill Bounties** (P5): a learner posts "Teach me X" and can attach a credit bounty. Mentors or instructors claim the bounty with a session or micro-course, and the bounty pays out when the learner accepts.

**Learning science**
8. **Interactive video** (P1): quiz checkpoints inside videos, chapter markers, and timestamped notes and Q&A pinned to video moments.
9. **Auto flashcards + spaced repetition** (P6): generated from lesson content (Workers AI), with an SM-2 review queue on the dashboard.
10. **AI Study Planner** (P6): takes a goal, a deadline and hours/week, then produces a weekly schedule with `.ics` calendar export, adapts when you fall behind, and sends reminder emails.
11. **AI Tutor scoped to the course** (P6): answers only from the lesson content (retrieval over Vectorize) and cites the lesson and timestamp. It doesn't just hand out exercise answers; it gives hints.

**Community and motivation**
12. **Study Pods** (P3): auto-matched accountability groups of 3–5 people by goal, timezone and pace. The pod shares a streak, has a pod chat and gets weekly pod goals.
13. **Leagues + Seasons** (P3/P6): weekly divisions with promotion and relegation (Duolingo-style) and 8-week seasons. Each season has a **free track + Plus premium track** of rewards (profile flair, streak freezes, exam discounts). This is a monetization lever that doesn't block learning.
14. **Skill Duels** (P3): real-time 1v1 quiz or coding battles on Durable Objects, with an ELO rating per skill.
15. **Guilds** (P6): user-created teams (colleges, companies, friend groups) with guild leaderboards and guild-vs-guild events. Colleges become a distribution channel.

**Social impact (brand + revenue)**
18. **Sponsor a Learner / Scholarships** (P6): individuals or companies (CSR budgets) buy seats or Plus months for learners who apply for scholarships. The funding goes on a public impact wall. The platform takes a small fee.
19. **Commitment Pledge** (P6): the learner deposits credits and gets them back when they finish by the deadline. Forfeited pledges go to the **scholarship fund**, not the platform, which keeps it ethical and legally clean. It is proven to raise completion rates.

22. **Regional pricing** (P7): purchasing-power-parity pricing when going global.

**Creator tools**

24. **Instructor coupons, bundles and pay-what-you-want** (P2): bundle discounts, early-bird pricing and PWYW with a minimum price.

## 10. Deployment (end to end)

1. **Accounts:** Cloudflare (free), domain on Cloudflare Registrar, Razorpay (test mode first), Resend, Google Cloud OAuth client, RapidAPI (Judge0), AdSense (after content exists).
2. **Provision** (scripted in `docs/operations/deployment.md`): `wrangler d1 create`, `wrangler r2 bucket create` (private plus public), `wrangler kv namespace create`, `wrangler queues create`. Durable Objects are declared in wrangler config.
3. **Environments:** `local` (miniflare), `staging` (`*.workers.dev`, separate D1/R2/KV) and `production` (your domain). Each is an `env.*` block in `wrangler.jsonc`.
4. **Secrets:** `wrangler secret put` for Razorpay, Resend, Google, session/encryption keys, Judge0 and the Turnstile secret.
5. **Deploy:** `npm run db:migrate:prod`, then `npm run deploy:api`, then `npm run deploy:web`. Workers Routes map `/api/*` to the api Worker. Cloudflare Access protects `/admin*`.
6. **DNS and security settings:** proxied, SSL Full (strict), HSTS, Bot Fight Mode, free WAF managed rules, `Always Use HTTPS`.
7. **Post-deploy:** smoke tests (Playwright against staging), Razorpay webhook URL registered, UptimeRobot on `/api/health`, Web Analytics on.
8. **Backups:** D1 Time Travel (point-in-time restore), plus a weekly `wrangler d1 export` to R2 (scripted). Restore runbook in `docs/operations/backups.md`.
9. **Upgrade path** (when traffic grows): Workers Paid ($5/month), then Cloudflare Stream for adaptive video, then D1 sharding or Postgres via Hyperdrive if the DB exceeds limits. Every step is documented.
