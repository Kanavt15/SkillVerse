# ADR 0002: D1 + Drizzle as the database

- **Status:** Accepted
- **Date:** 2026-09-23

## Context

The data is highly relational and financial: users, courses, enrollments, orders, ledger entries, payouts. We need constraints, joins and atomic multi-row writes. The database must work from Workers with no cold start, and be free to start. Options considered: MongoDB Atlas (free M0), MySQL, Neon Postgres via Hyperdrive, and D1.

## Decision

Use **Cloudflare D1** (SQLite) accessed through **Drizzle ORM**, with schema-first migrations generated by drizzle-kit and applied by Wrangler.

## Consequences

- ✅ Native binding with no network hop, connection pool or cold start, and free (5 GB total).
- ✅ Real SQL: foreign keys, unique constraints, indexes, FTS5 full-text search (used for course search).
- ✅ Drizzle gives typed queries, parameter binding (no SQL injection) and readable migrations. Its schema also works with Postgres, which is our exit path if we outgrow D1.
- ⚠️ 500 MB per database on the free plan (10 GB paid). Large blobs (videos, images, PDFs) go to R2, and D1 holds only metadata.
- ⚠️ No interactive transactions. See [ADR 0004](0004-d1-atomicity.md).
- ⚠️ Single-writer SQLite: very write-heavy features (view counters, analytics events) are aggregated before writing.
